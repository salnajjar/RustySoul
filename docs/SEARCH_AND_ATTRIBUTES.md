# File attributes and advanced searches

RustySoul advertises standard Soulseek file attributes where the media provides them: bitrate (code 0, kbps), duration (1, seconds), VBR/CBR (2, 1/0), sample rate (4, Hz) and bit depth (5, bits). Encoder code 3 is obsolete and is not invented. Attributes travel in both share listings and search replies and appear under file names in search and share views.

MP3 probing handles constant bitrate, Xing/Info and VBRI headers. CBR Info headers retain the nominal frame bitrate, so exact 192/320 kbps filters are not distorted by header or padding overhead. FLAC uses STREAMINFO. Property-only parsing extends coverage to WAV/WAVE, AIFF, APE, WavPack, AAC, Ogg/Vorbis, Opus, Speex, Musepack and MP4/M4A/M4B. ALAC and FLAC inside MP4 are distinguished from AAC; decoded PCM bit depth is not claimed for lossy files. Unsupported, malformed or incomplete metadata remains unknown. Sample rate is included for lossy formats too when known; bit depth is advertised only for lossless audio. VBR mode is reported only where the parser can establish it. Ambiguous container extensions remain under All formats; attribute filters can still identify their reported quality.

No media is decoded, no files are modified, and artwork/text tags are not retained. Generic probing has an 8 MiB read budget and a 1 MiB per-item parser allocation limit. A bounded property probe is skipped for files without a supported audio extension. Existing cached files are reprobed once for their format's extractor version during the next library scan (manual or automatic); later unchanged files are skipped normally. MP3 extractor upgrades preserve current cached metadata for other formats. The persistent cache and outgoing share index update together. Library startup-index and quiet scheduled-scan preferences retain their existing behavior.

Open **Advanced search filters** before or after starting a search. Minimum and maximum ranges support bitrate, duration, sample rate, bit depth and file size, with optional CBR/VBR and free-upload-slot restrictions. File sizes are entered in MiB; the API uses bytes. Leave bounds blank for no restriction. Active attribute bounds exclude files without that attribute, including zero-valued bounds. Filters apply to the complete SQLite search, live results, user counts, ordering and subsequent infinite-scroll pages. They are local reply filters: Soulseek's distributed search receives ordinary text terms, not a private filter syntax. **Clear advanced filters** removes them. File sorting also includes sample rate and bit depth.

The format, text and advanced filters can be combined. Equal minimum/maximum values select an exact quality, such as 16 bits and 44100 Hz. Read the attributes as reported metadata, rather than independent verification of audio provenance or transcoding quality.
