# Local protocol-library adapters

The MIT-licensed soulseek-rs-lib 20.0.0 source is pinned under vendor. Original copyright and license declarations remain intact. RustySoul adds:

- Cached share-index construction/replacement, avoiding repeated full metadata parsing.
- Shared upload/download payload budgets combining a total cap with one cap per user across simultaneous files, named overrides, short-read/write refunds, live changes, and cancellation-aware waits.
- Per-user upload reservations and atomic count-limit updates; finished upload-history clearing.
- Upload payload counters that exclude resumed prefixes from rate reporting, and more frequent download progress at low speed.
- Closed-peer actor handling: ignore late mailbox work, treat established remote resets as ordinary control-channel closure, and protect independent file connections when a control channel fails.

The application separately persists download intent and schedules negotiations under total and per-user download limits. The vendored library's unit suite is run with cargo test --manifest-path vendor/soulseek-rs-lib/Cargo.toml --lib; ordinary application tests also execute the exact shared-budget module and independent socket fixtures. See TESTING.md for current results and remaining interoperability/security gates.

- User discovery: expose explicit WatchUser existence replies, clear stale browse answers on a fresh request, surface send failures and preserve requests queued inside a failed outbound actor before brokered fallback. Real direct/reverse peer fixtures and an actor queue regression cover these changes.


Session/search/transfer milestone: independent caller-keyed searches support global, user, room and wishlist wire messages; drained responses retain total resource counters. Persistent ignore/ban workflows deny share browsing and uploads. Upload cancellation covers queued/offered/active transfers; duplicate requests and per-user/global upload queue sizes are bounded. Shared payload budgets expose direction totals incremented only after actual socket I/O; reservations/refunds and resume offsets are not counted. Peer upload-denied/failed messages retain their terminal download state until the daemon samples it, instead of immediately deleting it and leaving the application queue stuck. The loopback wire acceptance fixture now exercises a failed folder download, scheduled retry, exact file delivery and a resumed upload with precise aggregate accounting.


Profile/resilience update: peer-thread accounting now includes retiring actors and has a bounded grace reserve. Stop requests are signalled outside the mailbox so queued messages cannot delay shutdown indefinitely. Incoming handshakes are bounded at 32, use smaller explicit stacks and handle thread-spawn errors without panicking. Cgroup-limited deployments reserve task capacity for transfers and control workers. Actual payload byte deltas are attributed per username and drained only into pending durable accounting; unused reservations and resume offsets remain excluded. Public UserInfo replies now carry a saved description and optional bounded JPEG picture; interests reuse the existing like/dislike protocol methods.


Sharing/media/rooms update: retain bounded incoming UserInfo pictures with a 128-profile cache ceiling; add configurable upload eligibility checks using server share counts, buddy/named exemptions and explicit denials. Pending checks leave slots available to verified users. Periodic pumping refreshes stale checks and applies timeouts. Linux partial files reject symlinks and take an exclusive lock before mutation, protecting retries from concurrent writers. New socket fixtures verify no upload offer is sent to a zero-share requester and a sharing peer still receives exact resumed bytes.


Workspace/logs update: incoming transfer offers update the queued entry in place, preserving a reused token. Unrequested, finished, active, size-changed or conflicting offers receive a denial rather than an accidental acceptance. An unmatched incoming file socket is discarded as a late/unrequested connection. Pending file-token lookup retains a handshake permit until it is matched, keeping silent/unmatched sockets inside the admission budget. A protocol log observer forwards filtered warnings/errors to the daemon's bounded operational history.


Bulk upload cancellation snapshots and removes a user's queued and offered requests under one context lock, signals streaming cancellation, records terminal events, notifies peers and pumps other eligible work once. Offered uploads are included in upload snapshots with queue position zero while awaiting acceptance. Scoped cancellation never removes another user's offer.


Normal pre-handshake disconnects and a missing listening port followed by brokered fallback are debug events. Terminal peer/transfer failures remain visible; these recoverable connection stages no longer fill the error/warning history.

Social discovery: code 111 now reads both signed recommendation lists, matching the supplied Nicotine+ parser. The existing per-item getter returns both groups with signed ratings. A public `DiscoveryEvent` and `Client::drain_discovery_events` expose fresh replies, including empty answers, independently of cached getters. The backlog retains at most 16 replies; recommendation/user lists and per-item/user-interest caches are bounded. Tests exercise the second negative list and one-time bounded event draining. The application consumes only replies matching its active query and pending section, and independently caches validated data in SQLite.

Room controls: code 64 retains complete private owner/member/operator sections in a new PrivateList event. Code 14 retains private owner/operator metadata in PrivateJoined rather than discarding it; SDK live rosters handle private joins too. Code 141 now parses/forwards server invitation acknowledgements. Truncated private room lists and membership/operator rosters do not replace current authoritative data. Tests independently encode full/partial lists, private join suffixes and boolean acknowledgements. The ownership-cancellation method documentation now describes relinquishing ownership without promising deletion. Application permission checks, cached/live distinction, SQLite paging, persisted boards and pending confirmations sit above these wire events.

Chat/image update: peer UserInfo picture send/receive bounds allow up to 3 MiB so lossless 512x512 PNGs are not silently dropped. SDK profile-cache retention has both a 128-entry and 16 MiB aggregate picture budget. Unit fixtures cover large accepted payloads, oversized skips without field misalignment, and cache eviction. Room/private UTF-8 wire strings are unchanged.

Storage protection: optional `DownloadWriteGuard` hook, guarded partial writes with balanced reservations, `WaitingForSpace` terminal connection state retaining byte progress, typed capacity errors and quiet expected-hold logging. The daemon removes this SDK connection state before later requeueing; persisted UI state remains waiting rather than failed. The SDK continues operating without a guard for other callers. Tests cover exact partial resumption, failed-write release and actual Linux ENOSPC. The stress example recognizes the additional status.

Upload reliability: half-second connected-socket polls, cancellable partial handshake writes/offset reads, total offset handshake and progress-based data deadlines, own-rate-limit/local-read time exclusion, balanced allowance refunds on retries, typed `UploadStatus::TimedOut`, status-specific clearing, cancellation-safe late outcome handling and readable peer-disconnect warnings. Expired offers and brokered reverse connections are typed timeouts; peer control connection timeout logs are warnings. Tests cover silent and fragmented offsets, direct/reverse cancellation, blocked receivers, slow local limits, terminal-status races and history classification. The SDK public enum gains a variant; downstream exhaustive matches must handle it. Existing transfer byte framing and payload accounting are unchanged.

Privilege observation: each code-92 reply advances a per-client revision, including identical zero balances. New `Client::own_privilege_observation()` exposes `(seconds, revision)` alongside the unchanged legacy seconds accessor. `check_privileges` reports a closed server-actor channel as NotConnected. The daemon can distinguish a fresh reply from cached data without wire or database changes. SDK tests exercise successive zero replies.

Download reliability: network I/O timeouts publish the existing TimedOut variant and a stalled sender gets a readable 30-second inactivity message; local filesystem errors retain failure classification. Connected reads retry Interrupted and exclude local write latency from peer inactivity. Partial files retain an independent Linux parent descriptor, so daemon capability retirement cannot break finalization/cleanup. Idle cancellation cleanup takes the file lock; active workers remove their own locked inode, and Unix identity checks protect replacement partials. Retired/missing cancelled records and post-read cancellation are treated as cancellation, suppressing false Token not found errors. Expected peer failures are warnings rather than local errors. New socket/filesystem regressions cover real inactivity, retained retry offsets, active-file locks, replacement-inode protection and retired directory descriptors. Download byte framing and public DownloadStatus shape are unchanged; each active partial holds one additional parent descriptor until it finishes.


DownloadStore now atomically counts accepted offers/active or paused streams rather than plain remote queue waits, guards unsolicited file claims, expires unclaimed accepted offers after 30 seconds and reports capacity-only deferrals without retry failure. The application probes other users while peers are remotely queued. Upload ranking accepts saved per-file priority/order after the existing privileged-user class and before ordinary arrival order; accepted/streaming work is unchanged. Default SDK callers retain unlimited download admissions unless limits are installed. Unit and actual-wire fixtures cover slot races, lease expiry, donor precedence and real next-request/offer order.


A shared per-attempt DownloadProgress counter retains the exact locked partial-file length independently of terminal DownloadStatus variants and periodic speed reports. PartFile initializes it from the real resume offset, updates it after each write, and checks the file descriptor length after a failed write_all. Atomic counter updates add no threads or filesystem calls on successful writes. Unknown unopened progress differs from known zero; the application preserves existing SQLite progress for remote-queued retries until the writer opens the file. Final short fragments survive failure/timeout and completed progress remains the advertised size.

Nicotine+ interoperability: an offsetless EOF is accepted only for an empty upload after its token handshake; partial offsets and non-empty EOF remain failures. DownloadProgress also carries an independent per-attempt disconnect flag within its existing shared allocation. Client disconnect sets it for downloads and cancels active upload workers; paused, rate-limited and reading downloads exit quietly while retaining their partial files. A retired attempt cannot be resumed in place, and a new request has a fresh flag. DownloadError gains Disconnected for this intentional shutdown, distinct from cancellation/deletion. Tests cover direct/reverse empty handshakes, malformed/non-empty EOF, cancellation precedence, prefix/lock preservation and retired-attempt admission. See INTEROPERABILITY.md for real Nicotine+ coverage and the reference client's fragmentation limitation.

Soulfind/slskd interoperability: peer TransferRequest direction 0 now replies Queued before forwarding the filename to the existing upload admission path. It cannot create a local download reservation or bypass sharing/privilege/concurrency checks. Direction 1 retains requested-download validation; other directions receive a denial without enqueueing. A matched cancelled download receives Cancelled rather than a generic terminal-file rejection. Real-socket actor tests cover legacy and invalid directions. The optional server tests now assert current offered-position-zero, typed-timeout and explicit-negative-lookup semantics. All 87 cases ran against actual Soulfind with no missing-server/privilege-helper skips; slskd's actual client was tested independently in four pod cases. See SOULFIND_SLSKD.md.
