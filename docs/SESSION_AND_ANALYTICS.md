# Sessions, transfer history and bandwidth

The workspace restores its session when the browser refreshes. Sessions last up to 30 days and survive daemon restarts. Sign out revokes the session; changing the administrator account revokes all sessions. The UI never stores the token in localStorage or sessionStorage. Use HTTPS for remote access.

Uploads are grouped by username by default, and downloads offer the same Group by user option. Both pages load automatically as you approach the end of the loaded list, with an accessible Load more transfers fallback. Sorting/filtering run against the full SQLite history. In grouped mode the entire matching history for each admitted user is loaded, even when it exceeds the normal 100-file batch: one user has one section and the group count describes all matching files. Collapse all users and Expand all users establish defaults for users loaded later as well; individual toggles create exceptions until the next all-users action. Large expanded groups retain their data while mounting only nearby blocks of rows. Live transfer revisions refresh the loaded window in coalesced two-second checks; a refresh keeps existing rows visible until it can commit the replacement. Changing filters/order resets the loading window while preserving collapse defaults. History keeps the most recent state per peer and file; repeat transfers replace that row. Lifetime bandwidth counts every transfer independently.

The upload and download pages show lifetime file payload uploaded, downloaded and the upload/download ratio, plus both volume series over time. Range controls cover a day, week, month, year, all recorded time and custom dates. Earlier/later controls navigate windows; the graph slider inspects a time bucket. All graph dates and buckets use UTC.

Accounting begins when this version first initializes the database. Older transfer records cannot reconstruct exact payload volumes, retries or resume offsets, and are not used to invent totals. Actual reads/writes are counted, including partial transfers and retries, excluding resume offsets and protocol/TCP overhead. An upload counter measures bytes accepted by the local socket, not a remote disk acknowledgement.

SQLite commits deltas and bucket volumes in one transaction, normally every five seconds and at orderly disconnect/shutdown. Abrupt termination may lose the last uncommitted interval. Clearing transfer history never resets totals or graph history.

Retention is compact and automatic: seven days of minute buckets, ninety days of hourly buckets, then daily buckets indefinitely. Hourly compaction runs at startup and during operation; empty intervals use no rows. Only aggregate byte counts and timestamps are stored, never per-file/per-user graph records. Graph queries aggregate to roughly 720 points, irrespective of history length. Older/coarser buckets that overlap a selected range are included in full, which is stated beside the chart. History grows by at most one daily aggregate row per active day after the detailed retention windows; database page/WAL overhead depends on the installation.

Search/browse limits now protect resources without a 2,500-file UI cutoff. Defaults: 100,000 search results and 1,000,000 files per peer listing. Configuration can raise them to 1,000,000 and 2,000,000 respectively. Server/peer response size bounds and 30-second search windows still apply. Active transfer queue capacity remains explicit; large folder downloads fail atomically if capacity is insufficient. Completed history does not consume active queue capacity.


Per-user payload totals start with the profile/resilience update. Older global graph data remains intact but has no reliable peer attribution, so it is not used to invent per-user volumes. One SQLite aggregate row per username stores bytes uploaded/downloaded plus first and latest recorded transfer timestamps; there are no per-peer minute buckets. Upload group headers show both direction totals, and downloads can also be grouped by user. User ordering covers most/least data transferred in the current direction, newest/oldest first transfer, latest activity and username. Date ordering falls back to existing transfer-history dates for users without new payload samples. These totals survive history clearing. Retries now default enabled, with the existing bounded attempt/delay controls.


Both transfer pages now support ordinary single-file selection, Ctrl/Cmd toggles, Shift ranges across loaded virtual rows, and per-user full-group selection. Batch/per-user cancellation retains history and completed media; failed submissions retain their selection. Priority & queue controls persist local execution preferences independently of presentation sorts and preserve grouping/selection. See TRANSFER_QUEUE.md.
